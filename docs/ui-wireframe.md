# UI 와이어프레임 초안

상태: 합의한 초안. UI 및 아래 기능은 구현 완료를 의미하지 않습니다.

## 방향

VS Code 및 일반적인 코드 에디터와 비슷한 작업실 구조를 사용합니다. Electron 네이티브 메뉴바, 활동 바, 사이드바, 파일 탭, 편집 영역, 접을 수 있는 하단 패널, 상태바로 구성합니다. VS Code 확장 호환성은 제공하지 않습니다.

```text
┌──────────────────────────────────────────────────────────────┐
│ 파일  편집  보기  책  도구  도움말             Electron 메뉴 │
├────┬─────────────┬───────────────────────────────────────────┤
│    │ 책 탐색기   │ 1장.xhtml ×  스타일.css ×                 │
│활동│             ├───────────────────────────────────────────┤
│바  │ ▾ 본문      │ [일반 편집 | 코드 편집]  [미리보기]        │
│    │   1장       │                                           │
│    │   2장       │        편집 영역         │ 선택적 미리보기 │
│    │ ▾ 이미지    │                          │                │
│    │ ▾ 스타일    ├───────────────────────────────────────────┤
│    │             │ 변경 내용  검증 결과  내보내기 기록     ▾ │
│    │             │           선택한 하단 패널                │
├────┴─────────────┴───────────────────────────────────────────┤
│ 저장됨 · 1장                   글자 수 · 일반 편집 · EPUB    │
└──────────────────────────────────────────────────────────────┘
```

## 영역별 역할

| 영역 | 구성 및 동작 |
| --- | --- |
| 네이티브 메뉴바 | Electron에서 구현. 브라우저 UI 개발에서는 메뉴 명령을 테스트 가능한 대체 경로로 제공 |
| 활동 바 | 책 탐색기, 전체 검색, 미디어, 템플릿 전환 |
| 사이드바 | 선택한 기능의 목록과 설정. 접기 및 너비 조절 |
| 파일 탭 | 장과 CSS 파일 열기·선택·닫기. 미저장 변경 표시 |
| 중앙 편집 영역 | Tiptap 일반 편집과 Monaco 코드 편집 전환. 선택한 장과 작업 위치를 가능한 범위에서 유지 |
| 오른쪽 영역 | 필요할 때 미리보기 또는 속성 패널 표시. 기본적으로 선택적 분할 화면 |
| 하단 패널 | 변경 내용, 검증 결과, 내보내기 기록 |
| 상태바 | 저장 상태, 글자 수, 코드 위치, 작업 진행 및 출력 형식 표시 |

CSS 파일은 코드 모드로 편집합니다. 일반/코드 전환은 본문 문서에 적용합니다.

## 하단 패널 동작

- 하나의 패널에서 선택한 탭의 내용만 보여줍니다. 여러 탭 내용을 동시에 펼치는 구조가 아닙니다.
- 닫힌 상태에서 탭을 클릭하면 해당 내용을 펼칩니다.
- 펼친 상태에서 선택된 탭을 다시 클릭하거나 접기 버튼을 누르면 접습니다.
- 다른 탭을 클릭하면 열린 상태를 유지하며 내용만 전환합니다.
- 패널 경계를 드래그하여 높이를 조절하고 마지막 높이를 기억합니다.
- 패널을 접어도 편집 내용과 작업 결과는 유지합니다.
- 키보드로 탭 선택·패널 열기·접기가 가능하도록 구현합니다.

## 메뉴 초안

| 메뉴 | 항목 |
| --- | --- |
| 파일 | 새 책, 열기, 최근 책, DOCX 가져오기, 저장, EPUB/PDF 내보내기 |
| 편집 | 실행 취소, 다시 실행, 찾기·바꾸기, 이미지 삽입 |
| 보기 | 일반/코드 편집, 사이드바 표시, 하단 패널 표시, 미리보기 |
| 책 | 장 관리, 메타데이터, 표지, 목차, 템플릿·스타일 |
| 도구 | 책 검증, 변경 내용 확인 |
| 도움말 | 사용 안내, 앱 정보 |

프로젝트가 없거나 해당 파일에 적용할 수 없는 명령은 비활성화합니다. 세부 단축키와 기본 패널 크기는 UI 프로토타입에서 정합니다.

## 핵심 화면과 흐름

1. 시작: 새 책 만들기, 최근 프로젝트 열기, DOCX 가져오기.
2. 책 생성: 빈 책 또는 템플릿 선택, 기본 메타데이터 입력.
3. 작업실: 장 구성, 일반/코드 편집, 미디어 첨부, 선택적 미리보기.
4. 책 설정: 제목·저자·언어·표지·목차·스타일 관리.
5. 출력: EPUB/PDF 선택 → 하단 변경 내용 확인 → 출력 옵션 확인 → 내보내기.

저장은 PC에 작업 내용을 보존하는 동작입니다. 내보내기는 비교한 상태로 EPUB/PDF 결과물을 만드는 동작입니다. 저장할 때마다 출력 확인을 강제하지 않고, 내보내기 시 마지막으로 성공한 해당 형식의 기준본과 비교합니다. 첫 출력은 전체 내용을 확인합니다.

내보내기 성공 후에만 해당 형식의 비교 기준본을 갱신합니다. 취소·실패 시 유지하며, 검토 후 내용이 변경되면 다시 확인해야 합니다. 사용자는 Git을 설치하거나 배우지 않습니다. 화면에는 «변경 내용», «이전 내보내기와 비교», «확인 후 내보내기»를 사용합니다.

## UI 확정 전에 확인할 상태

- 프로젝트가 없는 상태, 빈 책, 장·이미지가 많은 책.
- 미저장 변경, 저장 진행, 저장 실패와 복구 안내.
- 지원하지 않는 XHTML, 잘못된 코드, 모드 전환 시 보존 안내.
- 변경 없음, 첫 내보내기, 텍스트 수정, 이미지 추가·삭제·교체.
- 검증 오류 선택 시 관련 파일과 위치로 이동.
- 내보내기 진행, 성공, 실패 및 재시도.
- 좁은 창, 패널 크기 조절, 키보드 탐색과 포커스 복귀.

## 후속 진행

먼저 이 초안으로 낮은 해상도의 와이어프레임과 클릭 가능한 UI 프로토타입을 만듭니다. UI 구조와 주요 작업 흐름을 검토한 뒤 [단계별 개발 계획](development-tasks.md)에 따라 기능을 진행합니다.
