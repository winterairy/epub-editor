# 단계별 개발 계획

상태: 계획. 이 문서의 체크박스는 아직 완료되지 않은 후속 작업입니다.

## 진행 원칙

UI 초안과 프로토타입을 먼저 검토한 뒤 기능을 단계별로 진행합니다. 각 Task는 구현, 의미 있는 검증, 실패 처리 및 문서 갱신을 포함합니다. 현재 기본 편집 화면과 라이브러리 설치를 기능 완료로 간주하지 않습니다.

작업실 구조는 [UI 와이어프레임 초안](ui-wireframe.md), 기술 선택은 [README](../README.md#기술-스택-결정사항)를 기준으로 합니다. DB는 현재 도입하지 않으며, 서버 기능을 확장할 때 Sonamu 도입을 제안합니다.

## 0단계: UI 초안 확정

- [ ] **UI-01 — 화면 와이어프레임:** 시작, 책 생성, 작업실, 책 설정, 변경 확인·내보내기 화면 구성. 빈 상태와 실패 상태 포함.
- [ ] **UI-02 — 클릭 가능한 프로토타입:** 활동 바, 사이드바, 파일 탭, 일반/코드 전환, 미리보기, 하단 탭의 접기·펼치기 및 크기 조절. 샘플 데이터임을 명시.
- [ ] **UI-03 — 메뉴와 작업 흐름 검토:** Electron 메뉴 명령과 화면 동작 연결 계획, 키보드 탐색, 저장과 출력의 구분 검토. UI 구조를 검토·확정한 후 1단계 시작.

완료 기준: «원고 가져오기 → 장 구성 → 편집 → 변경 확인 → 출력» 흐름을 프로토타입에서 따라갈 수 있고, 메뉴·패널·상태 표시의 역할이 정리되어 있음. 실제 저장과 출력의 구현 완료를 의미하지 않음.

## 1단계: 편집 기반

| Task | 개발 내용 | 완료 기준 |
| --- | --- | --- |
| TASK-01 | 책 프로젝트 생성·열기·저장, 폴더 구조와 데이터 모델, 제한된 Electron IPC, 최근 파일 JSON | 앱을 재시작하고 저장한 책을 동일하게 열 수 있음 |
| TASK-02 | 장 추가·삭제·순서 변경, 제목·저자·언어, 표지와 OPF 메타데이터 | 장 순서와 책 정보가 저장·복원됨 |
| TASK-03 | 일반 편집기의 제목·목록·인용·링크·표, 실행 취소·다시 실행. 이미지 노드는 TASK-07과 연동 | 지원하는 요소를 편집·저장하고 다시 읽을 수 있음 |
| TASK-04 | XHTML·CSS 코드 편집, 오류 표시, 모드 전환과 동기화, 지원하지 않는 구조의 보존 정책 | 전환 시 내용이 조용히 삭제되지 않고, 처리 불가능한 부분을 안내함 |
| TASK-05 | 자동 저장, 안전한 파일 교체, 복구본, 외부 변경 감지 | 비정상 종료 후 복구 가능하며 외부 변경을 무조건 덮어쓰지 않음 |

TASK-04의 문서 보존 가능성을 TASK-01과 함께 먼저 검증합니다. UI에서 안내한 보존 정책을 실제로 충족해야 합니다. Windows 기본 실행과 파일 경로 처리는 이 단계부터 검증합니다.

## 2단계: 원고와 책 구성

| Task | 개발 내용 | 완료 기준 |
| --- | --- | --- |
| TASK-06 | Mammoth DOCX 가져오기, HTML 정리, 이미지 추출, 제목 기반 장 분리, 별도 클립보드 붙여넣기 처리 | 한글·표·각주·이미지가 있는 실제 원고의 결과를 확인하고 편집·저장 가능 |
| TASK-07 | 이미지·GIF 첨부, 대체 텍스트, 크기 조정, 원본과 임시 가공본 관리 | 프로젝트 폴더를 옮겨도 미디어가 연결되고 원본이 보존됨 |
| TASK-08 | 소설·에세이 등 기본 템플릿, 구조와 CSS, 미리보기와 선택 적용 | 빈 책과 템플릿 기반 책을 만들 수 있고 기존 내용 덮어쓰기를 안내함 |

DOCX 이미지 추출은 TASK-07의 공통 리소스 저장 규칙을 사용합니다. 파일 가져오기와 복사·붙여넣기를 구분하여 검증합니다.

## 3단계: 출력과 변경 확인

| Task | 개발 내용 | 완료 기준 |
| --- | --- | --- |
| TASK-09 | XHTML·목차·OPF 생성, 리소스 수집, EPUB ZIP 패키징, EPUBCheck | 규격 검사를 통과하고 대표 리더에서 내용·목차·미디어가 표시됨 |
| TASK-10 | printToPDF, 인쇄 CSS, 용지·여백·페이지 나눔·글꼴, GIF 정지 프레임 | 한글·이미지·표가 누락되지 않고 페이지 배치가 검증됨 |
| TASK-11 | 형식별 기준본, 텍스트 diff와 미디어 비교, 검토한 상태 출력, 하단 패널 연결 | 성공 시에만 기준본 갱신. 취소·실패 시 유지하며 검토 후 변경은 재확인 |

TASK-09 → TASK-10 → TASK-11 순으로 진행합니다. 초기 출력 검증 경로와 사용자에게 제공할 최종 «확인 후 내보내기» 흐름을 구분합니다. 텍스트 비교용 이전 파일 내용은 보관하며 해시만 저장하지 않습니다.

## 4단계: 검색과 Windows 출시 준비

| Task | 개발 내용 | 완료 기준 |
| --- | --- | --- |
| TASK-12 | 책 전체 검색·결과 이동·바꾸기, 메모리 인덱스, 필요 시 SQLite FTS5 검토 | 한글 검색과 여러 파일 바꾸기를 확인·실행 취소 가능한 방식으로 처리 |
| TASK-13 | Windows 설치·업데이트·제거, 권한·경로, 코드 서명 준비, 실제 앱 전체 흐름 검증 | Windows에서 설치 → 원고 가져오기 → 편집·저장 → 변경 확인 → 출력이 동작 |

Windows 초기 실행 검증은 1단계부터 병행합니다. 업데이트 방식과 서명·배포 채널은 출시 준비 시 구체화합니다. Linux 브라우저 테스트를 Windows 앱 검증으로 대체하지 않습니다.

## 현재 범위에서 제외하거나 보류한 항목

- VS Code 확장 호환성 및 Code OSS 기반 앱 제작: 제외.
- Git 설치 요구, 사용자에게 commit·repository 등 Git 작업 노출: 제외. 내부 비교 엔진은 미확정.
- Word 페이지 배치의 완전한 재현: 목표에서 제외. 문서 구조를 가져와 책 스타일로 편집.
- 계정, 클라우드 동기화, 공동 편집, 공유 템플릿 서버: 후속 확장. 필요할 때 Sonamu 도입을 제안.
- 검색용 SQLite: 규모와 지속성 요구가 생길 때 검토. 본문과 미디어의 원본 저장소는 로컬 파일.
